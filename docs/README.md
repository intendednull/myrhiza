# Myrhiza docs

Master index of Myrhiza's design specs, plans, reports, and prior-art studies. Grouped by area for discovery.

For build/test/dev commands and project framing, see [`../CLAUDE.md`](../CLAUDE.md). For the doc-organization conventions, see the [`organizing-docs` skill](../.claude/skills/organizing-docs/SKILL.md).

## Document types

- **[Specs](specs/)** — what we are building toward. Target shape of the code.
- **[Plans](plans/)** — how we get from current code to the target.
- **[Reports](reports/)** — one-shot investigations of our own codebase (audits, post-mortems).
- **[Prior art](prior-art/)** — deep-dive studies on external systems we learn from.
- **[References](references/)** — curated indices of papers + talks anchoring a topic. Single-file; no deep-dive (that's `prior-art/`).

## Status tags

Specs/plans/reports carry one of:

- `[draft]` — being written, target not yet stable.
- `[active]` — current target / in-flight migration.
- `[landed]` — realized in code; canonical reference.
- `[superseded]` — replaced; entry links to successor.

Prior-art docs carry `[active]` or `[archived]`.

- [Plan B-12 — Stale-network backfill for revocation/publication logs](specs/2026-05-29-b-12-stale-network-backfill-design.md) — makes B-11's gossip-only distribution tier survive being offline: on-start + periodic HeadsSummary-shape sync over the per-author distribution topics (two append-only `GossipMessage` summary variants `RevocationHeads`/`PublicationHeads` at discriminants 5/6 — wire-freeze preserved), a kernel-side signed-envelope archive to serve backfill, and a 24h staleness surface (`RuntimeHandle::stale_authors`). **Transport corrected to direct-stream pull** (spec §14, superseding the original gossip-push §3.1/§3.4): the iroh-tier test proved gossip re-broadcast cannot catch up a *late joiner* over real iroh-gossip — a freshly-joined peer's broadcasts don't reach established peers (Plumtree eager/lazy asymmetry) + identical summaries are content-deduplicated, the same reason the event DAG uses pull. The landed mechanism mirrors `request_heads`: a behind peer hears the advertiser's above-its-head summary then **dials the advertiser** over a new `request_distribution` direct-stream protocol (`DISTRIBUTION_REQUEST_ALPN`, additive `Network` methods) to pull the missing envelopes from its archive; push + the amplification rate-limit are gone, replaced by a per-advertiser dial-limit (`DISTRIBUTION_DIAL_DAILY_CAP`). The two iroh-tier acceptance tests pass over real iroh-gossip, **closing `distribution.md` §10.7**. Realized by [plan B-12 (corrected transport)](plans/2026-05-29-b-12-direct-stream-pull.md). Cross-listed under App distribution. `[active]`
- [Plan B-13 — Kernel-mediated authoring](specs/2026-06-03-b-13-kernel-mediated-authoring-design.md) — connects an installed app's WASM `state-propose` component to the live `Runtime`'s sign+broadcast engine so apps emit events on the network: `Runtime` holds an optional `StateProposeHandle`; a new `AuthorCommand::ProposeAndAuthor { intent, reply }` + `RuntimeHandle::propose_and_author(intent)` runs the app's real `propose` against current state, then reuses `Runtime::author` **verbatim** (sign + pre-check + DAG insert + replay + broadcast). The private key stays kernel-side — **deliberately NOT `host.author-event`** (`architecture.md §3.5`: propose never sees a key; the `gating.rs` propose-rejects-`author-event` invariant stays green). Purely additive `crates/kernel` Rust: no new host import, no WIT change, no `GossipMessage`/wire change. New `RuntimeError::{NoProposeComponent, ProposeRejected}`; a buggy/malicious propose still can't bypass the kernel's `state-apply` dry-run. Realized by [plan B-13](plans/2026-06-03-b-13-kernel-mediated-authoring.md). Lands the produce-events half of the gap-analysis M1 milestone; subscribe + the kernel→interaction push bridge (M1b) remain open. `[landed]`

### Identity, crypto & trust

*(keys, MLS, capability custody, peer auth)*

- [Plan B-2 — Persistent identity + B-1 carryover cleanup](specs/2026-05-19-plan-b-2-persistent-identity-design.md) — bech32m-encoded `PeerKeypair` + `AuthorKeypair` filesystem store, `IdentityStore` trait, plus carryover fixes Q-4 (pending-peer attribution) and N-12 (handle_heads_summary refactor) from B-1 review. `[landed]`
- [MLS / OpenMLS](prior-art/mls/) — IETF Standards Track group key agreement protocol (RFC 9420, July 2023) plus OpenMLS Rust implementation (`openmls 0.8.1`, MIT). 13 files, ~1,560 lines. CGKA-based; O(log N) on member updates; FS + PCS; production-shipping at Wire (RFC 9420 GA April 2025), Webex (on draft, migrating), Discord DAVE (RFC 9420, A/V-only since Sept 2024), Google RCS UP 3.0 (limited rollout 2026). NOT used by Apple iMessage (uses PQ3), WhatsApp, Signal, or Matrix. Surfaces critical Cremers ETK 2025 finding (MLS fails FCGKA with EUF-CMA-only signatures like ECDSA — published-RFC-level flaw; use Ed25519 not ECDSA). OpenMLS does not ship as a WASM Component Model artifact; Myrhiza will need to author the WIT contract for `MlsGroup` operations. The reference cryptographic primitive if Myrhiza grows multi-party room-shaped capabilities (channels, group state-apply, multi-party caps with rotating membership). Consult before any spec on group caps, multi-party auth, or post-quantum migration. `[active]`
- [Reciprocity economy brainstorm](reports/2026-05-29-reciprocity-economy-brainstorm/README.md) — ideation + prior-art survey on anti-freeloading without a global token: per-peer private standing as a smooth function of cryptographically-attributed work imbalance, consumption-relative decay, graph-scaled grace buffer, `value()` placeholder (module-declared resource recipe × per-peer subjective shadow-prices), per-(peer,app) base scope. Closest prior art: GNUnet excess-based model, Bitswap/BitTorrent, Tribler TrustChain+MeritRank, market-based resource allocation. Feeds the named-but-unbuilt `myrhiza-participation-*` framework ([maintenance.md §12](specs/2026-05-09-myrhiza-master-design/maintenance.md)). Includes full transcript. Flags GNUnet + market-based-allocation as prior-art gaps. `[active]`

### P2P runtimes

- [Holochain](prior-art/holochain/) — peer-symmetric Rust runtime hosting WASM apps with deterministic-validation DHT. Closest architectural neighbor; consult when designing capabilities, determinism, networking, or identity. `[active]`
- [Pears / Holepunch](prior-art/pears/) — JavaScript-based consumer-mobile P2P stack: Hypercore (signed append-only log) + Hyperswarm (DHT + UDP holepunching, Noise-IK) + Bare (mobile-embeddable JS runtime) + Pear runtime + Keet messenger (closed-source flagship; iOS+Android, low-tens-of-thousands MAU). 17 files, ~3,550 lines. Single-vendor stewardship by Holepunch Inc, Tether-funded. Mixed MIT (Dat-era cores) / Apache-2.0 (Holepunch-era). The closest existing-art for state-apply event log substrate (Hypercore = append-only signed) and consumer-mobile P2P UX (Keet's iOS push-relay, suspend/resume). Not WASM — design lessons only, no API commitments. `[active]`
- [Spritely Goblins / OCapN](prior-art/spritely-ocapn/) — distributed object-capability runtime + cross-implementation network protocol (with Agoric, MetaMask, Cap'n Proto). Closest semantic neighbor on capability discipline; consult when designing the cap layer, distributed GC, sturdyrefs, promise pipelining, or netlayer abstraction. `[active]`
- [Agoric / Endo / SwingSet](prior-art/agoric-endo/) — production-hardened ocap + deterministic-replay JavaScript runtime; Cosmos chain since 2022-10-27, MetaMask Snaps in production at scale. Cousin to Spritely on the E lineage; the load-bearing reference for our `state-apply` purity, vat-snapshot/replay, computron metering, and the bundle-hash story. Consult before any spec on determinism, component upgrade, distributed GC, or app bundling. `[active]`
- [AT Protocol / Bluesky](prior-art/at-protocol/) — federated client-server protocol behind Bluesky social; primary steward Bluesky Social PBC (Delaware PBC, incorporated 2021-10, benefit conversion 2022-02). 15 files, ~1,940 lines. `did:plc` rotation-key / `#atproto` signing-key separation is the deployed reference for Myrhiza's multi-device-identity open problem — long-term identity (DID document with up-to-5 rotation keys, 72-hour clobber window) decoupled from active signing key. Architecture is **federation-shaped, not P2P**: ~99% of users on Bluesky-operated PDS/Relay/AppView tiers as of early 2026 ($100M Series B 2026-03; ~27.5M MAU per third-party estimates; Jay Graber → CIO 2026-03-09, Toni Schneider interim CEO). Lexicon (NSID-namespaced schema language) is the canonical answer to schema-versioned records in a federated repo. No native E2E for DMs as of 2026; Germ (Feb 2026) overlays MLS on atproto identity as a third-party answer. MIT. Sync v1.1 cutover 2026-01-27; BGS → Relay rename 2023-11-10. **Identity primitives are excellent prior art; federation story is a cautionary tale about what "federation" looks like when only one operator can afford the central tier.** Consult before any spec on multi-device identity, key rotation, lexicon-style schema versioning, or federation-vs-P2P trade-offs. `[active]`
- [Willow](prior-art/willow/) — **internal architectural ancestor** of Myrhiza. P2P Discord replacement (Rust + Leptos + iroh + Ed25519 + ChaCha20-Poly1305 + X25519 + HLC), 15 production crates, ~30 specs, ~38 plans, single-author project (@intendednull, [github.com/intendednull/willow](https://github.com/intendednull/willow)). 16 files, ~3,800 lines. Captures the per-author Merkle DAG event-sourcing model, actor framework + lock-discipline, dual-target native+WASM compilation discipline, iroh trait abstraction (`Network`/`TopicHandle`/`BlobStore`), test-tier hierarchy, and PR #636's draft master-runtime spec — the *proto-spec for Myrhiza*. The four-component-profile table (`state-apply` strict / `state-propose` loose / `interaction` / `behavior`), pre-check-equals-apply mechanic, capability-only host surface, and key-handles-not-bytes custody story were lifted from PR #636 directly into Myrhiza CLAUDE.md. Open problems Willow surfaced (distributed maintenance + Sybil-resistant participation, multi-device identity, MLS adoption shape, hot-reload, snapshot portability) are inherited as Myrhiza's. Framing disclosure: written from a "Myrhiza-as-generalization-of-Willow" stance — not a neutral catalog. Consult before any spec on `state-apply` ABI, kernel capability surface, key custody, sync protocol, actor topology, worker security model, UI app contract, distributed maintenance, or MVP demo app shape. `[active]`

### Networking substrate

- [Iroh](prior-art/iroh/) — Rust P2P stack from Number 0: dial-by-pubkey QUIC, content-addressed blobs, NAT traversal via DERP-derived relays. **Load-bearing dependency** Myrhiza is committing to as transport substrate; consult before any kernel-network-cap, app-bundle-distribution, or peer-identity spec. `[active]`
- [libp2p / gossipsub](prior-art/libp2p/) — Protocol Labs' modular P2P networking stack across rust-libp2p (MIT, v0.56.0 crates.io / v0.57.0 master), go-libp2p (MIT, v0.48.0 2026-03-17), js-libp2p (Apache-2.0/MIT, v3.3.1), nim-libp2p (vacp2p), cpp-libp2p (Soramitsu), jvm-libp2p (ChainSafe). 13 files, ~2,120 lines. Origin: spun out of go-ipfs 2015–2016 by Juan Benet. Largest deployment is the **Ethereum consensus layer** (all 5 beacon clients: Prysm, Lighthouse, Teku, Nimbus, Lodestar — ~1M+ active validator keys, ~10k+ full nodes); then Filecoin, IPFS (`kubo`), Polkadot/Substrate, Status/Waku. **Algorithms are load-bearing for Myrhiza, the framework is not** — Myrhiza picked iroh. But Myrhiza adopts epidemic-gossip pub/sub via `iroh-gossip` which uses **HyParView + Plumtree, not gossipsub itself** (the most-load-bearing factual clarification in this folder). Gossipsub spec lifecycle: v1.0 (3A) / v1.1 (2A, score function — the real production version) / **v1.2 — not v2.0** (IDONTWANT only). Kademlia DHT (k=20/α=10), Noise XX handshake, QUIC primary transport, WebRTC browser transport. Consult before any spec on gossip mesh topology, peer scoring, DHT design, multistream-select, or libp2p-vs-iroh trade-offs. `[active]`
- [Anonymity transports (Tor / Veilid / I2P / Nym / HOPR)](prior-art/anonymity-transports/) — netlayer-plugin survey: **Tor** (0.4.9.8, BSD-3, 501c3 Tor Project, ~7K relays / 2–4M daily users) + **arti** (2.0.0 Rust, MIT/Apache-2.0); **Veilid** (0.5.3, MPL-2.0, Cult of the Dead Cow 501c3, DEF CON 31 unveiling 2023-08-11); **I2P** (2.12.0 Java / 2.60.0 i2pd, 2003); **Nym** (Apache-2.0 + NYM token, Loopix mixnet); **HOPR** (GPL-3.0 + HOPR token). 8 files, ~1,780 lines. Plus academic ancestors: Chaum 1981 (CACM) and Loopix (Piotrowska et al., USENIX Security 2017). Cited in [`willow/open-problems.md:207-218`](prior-art/willow/open-problems.md) (topic-ID rotation via Tor v3 descriptor blinding) and [`iroh/lessons.md:34`](prior-art/iroh/lessons.md) (iroh-on-Tor / iroh-on-Veilid plug-in). Load-bearing finding: Tor v3's `blinded-id = ed25519-scalar-mult(root-key, H(period, srv))` is the smallest cryptographic primitive that delivers unlinkability across rotation periods — directly applicable to Myrhiza's topic-ID rotation child spec. **Honest framing:** anonymity is a layer of layers (transport / sealed-sender / E2E content / pattern-traffic); no single transport delivers it. Consult before any spec on topic-ID rotation, netlayer plug-in API, or transport-anonymity claims. `[active]`
- [WebRTC for browser P2P](prior-art/webrtc/) — the browser's only direct-peer transport. 9 files, ~1,390 lines. Stack: W3C `webrtc` REC (latest 2025-03-13), RFC 8825 overview, ICE/STUN/TURN (RFCs 8445/8489/8656), DTLS-over-UDP + SCTP framing, mDNS-for-ICE (`draft-ietf-mmusic-mdns-ice-candidates-03` expired 2021-12 but shipped in browsers). Implementations: `webrtc-rs` (Tokio, 5k★, v0.17.1), **`str0m`** (Sans-IO Rust, 552★, v0.19.0 — kernel-friendly), `libdatachannel` (MPL-2.0 C++, 2.6k★, v0.24.3), `pion/webrtc` (Go canonical, 16.5k★, v4.2.13); `simple-peer` is stale (2022-02). libp2p-webrtc spec (Candidate Recommendation 2023-04-12) gives the transport-pluggable model — browser-to-server stable, browser-to-browser newer. **WebRTC is NOT "P2P"** without nuance: requires out-of-band signalling, 10–30% of real-world connections fail without TURN relay. WebTransport (Chrome 97+ / Firefox 114+ / Safari 26.4) is the modern client-server alternative, not a WebRTC replacement. - [Resource-pricing theory — NUM, shadow prices, and the DRF challenge](prior-art/resource-pricing-theory/) — multi-topic survey, 7 files, ~420 lines. The formal foundation **and** the load-bearing critique of the reciprocity model's `value_P = resource_vector·shadow_prices`. **Kelly NUM** (Kelly/Maulloo/Tan, JORS 1998) — a route's price = Σ per-link shadow prices = the dot-product, and shadow price = Lagrange multiplier = opportunity cost (LP duality); legitimizes the metric as a sound *local* Lagrangian — with the caveat that NUM optimality needs cross-peer reconciliation, so unreconciled local prices are a *heuristic, not a proven dual*. **DRF** (Ghodsi et al., NSDI 2011; shipped in Mesos/YARN) — its *Asset-Fairness* baseline *is* the priced dot-product, and Theorem 1 proves it violates sharing-incentive (a user worse off than a static equal split), while DRF allocates over the resource vector with no prices. Takeaway: use the dot-product only as a cost/credit *metric*, never the allocation rule; pair with a dominant-resource bottleneck rule. Plus DRFH (heterogeneous servers), the Leontief non-substitutability point, and ConEx (IETF Experimental congestion-pricing-as-accountability). Consult before specifying the reciprocity `value()` metric or the allocation/enforcement side. `[active]`
- [Market-based control — the computational-economy paradigm](prior-art/market-based-control/) — multi-paper survey, 8 files, ~820 lines. The lineage `value_P = resource_vector·shadow_prices` descends from, and its 50-year record of mostly *not* deploying. Sutherland 1968 (PDP-1 futures market) → Miller & Drexler "Agoric Open Systems" 1988 → **Spawn** (Waldspurger et al., IEEE TSE 1992; sealed-bid second-price auctions) → **Tycoon** (HP Labs, proportional-share-by-bid). The damning tell: Waldspurger built Spawn, then abandoned it for price-free lottery/stride scheduling (1994), and the price-free design shipped (Linux CFS lineage) while the market did not. **Mirage vs Bellagio** adoption post-mortems — a market survives only as the mandatory sole path to a scarce binding resource; both needed a savings-tax to stop scrip hoarding. Key lesson: Myrhiza's per-peer *local crediting ledger* (not a live auction) sidesteps the volatility/discovery/bid-UX cluster that killed these systems. Explicitly **not** an extension of `agoric-endo/` (the SES company vs the market-control paradigm); sharpens its "tokenomics are not a runtime concern" tension. Consult before any spec that prices resources or contemplates an auction. `[active]`
