  ```rust
  fn apply(prior_state: Vec<u8>, event_bytes: Vec<u8>) -> (Verdict, Vec<u8>) {
      // Decode just the seq + payload bytes from the canonical-bincode
      // Event envelope. (Counter uses a hand-rolled byte parser for the
      // float-Display avoidance reason; mirror exactly.)
      let (seq, payload) = match parse_seq_and_payload(&event_bytes) {
          Some(parts) => parts,
          None => return (Verdict::Reject("malformed event".into()), prior_state),
      };

      if seq == 1 && prior_state.is_empty() {
          // Genesis: extract initial state from GenesisV1::app_payload.
          // Use the SAME GenesisV1-byte-skip pattern counter uses to
          // extract the app_payload without pulling in bincode/serde.
          let app_payload = match parse_genesis_app_payload(&payload) {
              Some(bytes) => bytes,
              None => return (Verdict::Reject("malformed genesis".into()), prior_state),
          };
          (Verdict::Accept, app_payload)
      } else {
          // Non-genesis: state = event payload (overwrite semantics).
          (Verdict::Accept, payload)
      }
  }

  fn state_digest(state: Vec<u8>) -> Vec<u8> {
      // Identity. Mirrors counter's lib.rs:239-244 pattern.
      state
  }
  ```

  Reference the counter fixture's `parse_seq_and_payload` and `parse_genesis_app_payload` (or equivalent) helpers. If they're inline-implemented in counter's lib.rs, copy them verbatim. If they're not factored, do the same kind of inline parsing in echo.

## Task 3: Coexistence acceptance test

**Files:** new `crates/kernel/tests/coexistence.rs`.

**Spec:** §3.5, §4.

- [ ] **Step 3.1: Create the test file with smoke + criterion 4 tests**

  Two tests in one file:

  1. **`kernel_instantiates_and_applies_echo`** (smoke) — mirrors `acceptance.rs::kernel_instantiates_and_applies_increment` but for echo. Loads the echo bundle, applies a genesis event (with `GenesisV1::app_payload = b"hello".to_vec()`), then a non-genesis event with payload `b"world".to_vec()`; asserts the final state equals `b"world"`.

  2. **`two_apps_coexist_no_event_crossing`** (criterion 4) — same-peer two-runtime test per spec §3.5.

  Use `helpers::counter_handle()` and `helpers::echo_handle()`. The peer keypair is constructed twice via `PeerKeypair::deterministic(501)` (PeerKeypair doesn't impl Clone; deterministic returns the same key both times — exactly the pattern B-4.5 Task 5 established for `runtime_a` reuse).

  Author one event on each runtime (Increment(+5) on counter, payload `b"hello"` on echo). Wait for both runtimes to settle their own state. Assert:
  - `runtime_counter.dropped_at_apply.lock().unwrap().is_empty()` — counter didn't reject any cross-topic event.
  - `runtime_echo.dropped_at_apply.lock().unwrap().is_empty()` — same for echo.
  - The digests differ AND match their expected per-app state (counter = 5, echo = `b"hello"`).
  - No `PeerWarning::SignatureInvalid` in either runtime's `peer_warnings` (cross-topic injection would have surfaced this since the events would be properly-signed for their own topic but received as garbage on the other).

  Use the `coexistence.rs::two_apps_coexist_no_event_crossing` skeleton from spec §3.5 but adapt the assertion shape to match the actual `RuntimeHandle` fields (`digest_watch: tokio::sync::watch::Receiver<Vec<u8>>`, `dropped_at_apply: Arc<Mutex<HashMap<EventHash, String>>>`, `peer_warnings: Arc<Mutex<Vec<PeerWarning>>>`).

  Include `/// Covers: convergence.md §4.6` (the topic-identity section is the master-spec home for this property; or use the same coverage cite as the existing `coexistence_two_topics_no_event_crossing` test).
