# Plan B-4.3: Halt-on-persistent-transport-error — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pay off the B-4.1 §6 deferred item ("ApiError mid-stream — runtime will spin if gossip task has died; deferred to B-4.3"). Add `SubError::TransportError(String)` variant distinct from `Lagged`/`DecodeFailed`. Map iroh-gossip mid-stream `ApiError` to `TransportError` (was `Lagged(0)`). Runtime accumulates consecutive `TransportError`s in a per-task counter and halts via the existing `halt_watch_tx` after a configurable threshold (default 5). New `PeerWarning::TransportError { reason, consecutive }` variant for observability. New `MemBus::inject_transport_error()` test affordance mirroring `inject_lag`.

**Architecture:** Receive-side only. No wire format changes. Counter is strict-consecutive: increments only on `TransportError`, resets only on `Ok(Some(_))`; `Lagged` and `DecodeFailed` are neutral (neither increment nor reset). Halt-and-report (no auto-recovery) — the embedder constructs a new `Runtime` if recovery is desired.

**Tech Stack:** Rust 1.95 (edition 2024). No new dependencies.

**Spec:** `docs/specs/2026-05-20-plan-b-4-3-halt-detection-design.md` (audit-cleared in `c6bece4`).

**Branch:** `feat/plan-b-4-3-heads-request-direct-streams` (despite the branch name — this slice's scope is JUST halt detection; direct-streams deferred to B-4.4). 2 commits ahead of main: spec + audit revisions.

- [ ] **Step 1.7: Add `MemBus::inject_transport_error` method**

After the existing `inject_lag` method (around `memory.rs:111-127`):

```rust
/// Arm every live subscription on `topic` so that its next `recv`
/// returns `Err(SubError::TransportError("injected by ..."))`
/// exactly once, then resumes normal delivery.
///
/// Gate-paired with [`MemBus::inject_lag`]: both are deterministic
/// test affordances that bypass the natural-overflow / natural-actor-
/// death paths which are timing-dependent and hard to assert against.
///
/// Per B-4.3 spec §3.4.
///
/// # Panics
/// Does not panic. Mutex poisoning is recovered transparently.
#[cfg(any(test, feature = "test-helpers"))]
pub fn inject_transport_error(&self, topic: Topic) {
    let mut topics = self
        .topics
        .lock()
        .unwrap_or_else(std::sync::PoisonError::into_inner);
    if let Some(state) = topics.get_mut(&topic) {
        state.force_transport_error_flags.retain(|w| w.strong_count() > 0);
        for weak in &state.force_transport_error_flags {
            if let Some(flag) = weak.upgrade() {
                flag.store(true, Ordering::SeqCst);
            }
        }
    }
}
```

    Ok(Some(m)) => {
        self.consecutive_transport_errors = 0;
        let _ = self.handle_message(m).await;
    }
    Ok(None) => return Ok(()),
    Err(SubError::Lagged(n)) => {

        self.peer_warnings
            .lock()
            .expect("peer_warnings mutex poisoned")
            .push(PeerWarning::BroadcastLagged { dropped: n });
        self.publish_heads_summary().await?;
    }
    Err(SubError::DecodeFailed { peer }) => {
        // existing DecodeFailed handler — unchanged.
        #[allow(clippy::expect_used)]
        self.peer_warnings
            .lock()
            .expect("peer_warnings mutex poisoned")
            .push(PeerWarning::DecodeFailed { peer });
    }
    Err(SubError::TransportError(reason)) => {
        self.consecutive_transport_errors += 1;
        if self.consecutive_transport_errors >= self.cfg.transport_error_halt_threshold {
            let halt_msg = format!(
                "transport halted: {} consecutive errors (latest: {})",
                self.consecutive_transport_errors, reason

            return Ok(());

        self.peer_warnings
            .lock()
            .expect("peer_warnings mutex poisoned")
            .push(PeerWarning::TransportError {
                reason,
                consecutive: self.consecutive_transport_errors,
            });
    }
},
