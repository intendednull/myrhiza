## Task T0 — Spike: verify `[[bin]] + required-features` on wasm32-unknown-unknown

**Spec ref:** §3.3 risk row 2; §6 risk row 2.

**Subject:** Prove the load-bearing Cargo shape works before sinking implementation effort into it. The spec calls out that `[[bin]] + required-features` interacting with `--target wasm32-unknown-unknown` is the highest-likelihood "needs verification" item. If it fails here, the fallback (three separate `examples/counter-*/` crates) reshapes T5 and T6.

**Acceptance:**

- Concrete: an empty stub crate under `.spike/b-8-bin-required-features/` (NOT under `examples/` — this is throwaway) builds a `.wasm` file via `cargo build --target wasm32-unknown-unknown --features state-apply --bin spike-bin` and the output is a valid wasm32 artifact (non-zero size, starts with `\x00asm` magic per `xxd path | head -1`).
- Documented: T0 commit body records "spike PASSED — proceeding with single-crate shape" OR "spike FAILED with <error> — escalate to plan reviewer for fallback decision."
- Time-boxed: 1 hour. If the spike isn't producing wasm in 1 hour due to Cargo plumbing issues (not real toolchain bugs), declare FAIL and switch to fallback.

**How the implementer knows the spike failed (vs. slow):**

A pass is "wasm-tools magic header present in the output file" — that is a single byte comparison, not a timing observation.

A failure is one of these concrete diagnostics on `cargo build`:
- `error: the `[[bin]]` target `spike-bin` has `required-features = ["state-apply"]` which does not exist` — Cargo doesn't understand the feature gating.
- `error: linking with `rust-lld` failed: exit status: 1` followed by `lld: error: undefined symbol: __main_void` — `[[bin]]` and `cdylib` collide on `_start` / `__main_void` symbols.
- The build produces only `libspike_bin.rlib` and no `.wasm` — wasm32 ignores `[[bin]]` and only emits the `[lib]`.
- The build succeeds but the produced file is `target/wasm32-unknown-unknown/release/libspike_bin.rlib` instead of `.wasm` — same symptom, different name.
- The build hangs with no output for >2 min — this is a toolchain or sccache wedge, not a config bug. Kill the process and re-try with a clean target dir (`rm -rf target/`); if it still wedges, the toolchain itself is sick (separate issue, escalate).

Slowness is NOT a failure signal — cold compile of an empty crate on wasm32 takes 10–30 seconds for `wit-bindgen` codegen alone. The spike's failure modes are mechanical (Cargo rejects the config, linker errors, wrong output artifact). If the build is just slow, wait for it. The >2 min no-output threshold above is the cutoff between "slow" and "wedged."

**Files:**

## Task T2 — `manifest!` declarative macro + unit tests

**Spec ref:** §2.6, §3.2 (macro body sketch).

**Subject:** Implement the `manifest!` declarative macro. App authors write their manifest as Rust syntax that expands to a canonicalized `Manifest` struct. Schema validation surfaces at the author's compile time, not at install time.

**Acceptance:**

- `cargo test -p myrhiza-sdk --test manifest_macro` passes.
- Three explicit tests pass: (a) the macro expansion matches a hand-built `helpers_only_three_component_manifest` field-for-field via `assert_eq!`, (b) `canonicalize()` is idempotent after macro expansion (calling it again produces the same `Manifest`), (c) missing required sections fail to compile (negative tests via doc-comment-as-compile-fail or a `trybuild`-style fixture if we want strict coverage).

**Files:**

- Create: `crates/sdk/src/macros.rs` — the `manifest!` macro body + helper sub-macros `__author_class!`, `__sdf!` for ident → enum-variant translation.
- Modify: `crates/sdk/src/lib.rs` — add `pub mod macros;`.
- Modify: `crates/sdk/src/prelude.rs` — add `pub use crate::manifest;` (the macro is `#[macro_export]`-ed; this line re-exports it from prelude).
- Create: `crates/sdk/tests/manifest_macro.rs` — integration tests exercising the macro.

**Implementation notes:**

The macro lives in `src/macros.rs` and is `#[macro_export]`-ed so the prelude re-export works. Concrete sketch (spec §3.2 has the full body):

```rust
#[macro_export]
macro_rules! manifest {
    (
        app {
            name: $name:literal,
            version: $version:literal,
            description: $description:literal,
            author_class: $class:ident,
        }
        abi {
            kernel_major: $kmaj:literal,
            kernel_minor_min: $kmin:literal,
            state_digest_format: $sdf:ident,
        }
        capabilities {
            $( deterministic_helpers: [ $($helper:literal),* $(,)? ] , )?
            $( host_imports: [ $($hi:literal),* $(,)? ] , )?
        }
        components {
            $( state_apply: $sa:literal , )?
            $( state_propose: $sp:literal , )?
            $( interaction: $ix:literal , )?
            $( behavior: $bh:literal , )?
        }
    ) => {{
        use $crate::manifest::*;
        let mut m = Manifest {
            app: AppSection {
                name: $name.into(),
                version: $version.into(),
                description: $description.into(),
                author_pubkey: String::new(), // filled at signing time
                author_identity_class: $crate::__author_class!($class),
            },
            abi: AbiSection {
                kernel_major: $kmaj,
                kernel_minor_min: $kmin,
                state_digest_format: $crate::__sdf!($sdf),
            },
            capabilities: CapabilitiesSection {
                deterministic_helpers: {
                    #[allow(unused_mut)]
                    let mut h = ::std::collections::BTreeMap::new();
                    $( $( h.insert($helper.into(), true); )* )?
                    h
                },
                host_imports: {
                    #[allow(unused_mut)]
                    let mut h = ::std::collections::BTreeMap::new();
                    $( $( h.insert($hi.into(), true); )* )?
                    h
                },
                ui_surfaces: ::std::collections::BTreeMap::new(),
                high_value_ops: HighValueOps::default(),
            },
            determinism: DeterminismSection {
                allow_floats: false,
                drift_detection: DriftDetectionSection { interval_events: 1024 },
            },
            modules: ModulesSection { dep: vec![] },
            components: ComponentsSection {
                state_apply: $crate::__opt_lit!($($sa)?),
                state_propose: $crate::__opt_lit!($($sp)?),
                interaction: $crate::__opt_lit!($($ix)?),
                behavior: $crate::__opt_lit!($($bh)?),
            },
            author_policy: AuthorPolicy::default_deny(),
            signature: None,
        };
        m.canonicalize();
        m
    }};
}

#[doc(hidden)]
#[macro_export]
macro_rules! __author_class {
    (third_party) => { $crate::manifest::AuthorIdentityClass::ThirdParty };
    (myrhiza_official) => { $crate::manifest::AuthorIdentityClass::MyrhizaOfficial };
}

#[doc(hidden)]
#[macro_export]
macro_rules! __sdf {
    (bincode13) => { $crate::manifest::StateDigestFormat::Bincode13 };
}

#[doc(hidden)]
#[macro_export]
macro_rules! __opt_lit {
    () => { None };
    ($lit:literal) => { Some($lit.into()) };
}
```

**Determinism callout:**

The `manifest!` macro emits a `Manifest` struct that is structurally identical to today's hand-rolled fixtures. The struct's `canonicalize()` method (per `crates/manifest/src/schema.rs`) is responsible for normalizing the canonical form (sorting BTreeMap entries, etc.). The macro is NOT state-apply code; determinism rules apply only to the resulting bincode encoding at signing time, which `crates/manifest/src/canonical.rs` handles unchanged.

**Risk:**

- Test (a) compares a macro-expanded struct to a hand-built struct. If `canonicalize()` produces a different ordering than expected, both sides will see the same canonicalized form (`PartialEq` derive on `Manifest` compares field-for-field, not by canonical encoding). The test passes by construction if the macro emits the same fields. **The test catches**: drift in defaults (e.g., if a contributor changes `AuthorPolicy::default_deny()` to a different default, the macro and hand-built diverge).
- `compile_error!` for missing required sections is not part of v1 acceptance per spec §2.6 ("documented in macro docs"). A `trybuild` test setup is more than B-8 needs; defer to a follow-up.

```rust
//! Boilerplate types emitted by the `myrhiza_app!` macro.
//!
//! Gated to `target_arch = "wasm32"` because the bump allocator and
//! `#[global_allocator]` mechanism are only meaningful in wasm
//! component crates. Host-side consumers of `myrhiza-sdk` (e.g.,
//! manifest builders) never reference these items.
//!
//! The macro emits `static GLOBAL: BumpAlloc = BumpAlloc;` and
//! `#[global_allocator]` at the consumer crate's root; the items in
//! this module are the type definitions the macro references.

use core::alloc::{GlobalAlloc, Layout};

const HEAP_SIZE: usize = 64 * 1024;

#[repr(C, align(16))]
struct BumpHeap {
    bytes: core::cell::UnsafeCell<[u8; HEAP_SIZE]>,
    next: core::sync::atomic::AtomicUsize,
}

#[allow(unsafe_code)]
unsafe impl Sync for BumpHeap {}

#[allow(unsafe_code)]
static HEAP: BumpHeap = BumpHeap {
    bytes: core::cell::UnsafeCell::new([0; HEAP_SIZE]),
    next: core::sync::atomic::AtomicUsize::new(0),
};

/// Bump allocator the `myrhiza_app!` macro installs as the consumer
/// crate's `#[global_allocator]`.
///
/// State-apply runs a fresh wasmtime instance per (event, peer); the
/// kernel discards the store after each call so we never actually
/// need to free. A bump allocator is the smallest thing that
/// satisfies the `extern crate alloc` requirement without pulling in
/// float-Display paths from any of the ecosystem crates.
pub struct BumpAlloc;

#[allow(unsafe_code)]
unsafe impl GlobalAlloc for BumpAlloc {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        use core::sync::atomic::Ordering;
        let align = layout.align().max(1);
        let size = layout.size();
        let base = HEAP.bytes.get() as usize;
        let mut cur = HEAP.next.load(Ordering::Relaxed);
        loop {
            let aligned = (base + cur + (align - 1)) & !(align - 1);
            let new_cur = (aligned - base).saturating_add(size);
            if new_cur > HEAP_SIZE {
                return core::ptr::null_mut();
            }
            match HEAP
                .next
                .compare_exchange_weak(cur, new_cur, Ordering::Relaxed, Ordering::Relaxed)
            {
                Ok(_) => return aligned as *mut u8,
                Err(observed) => cur = observed,
            }
        }
    }

    unsafe fn dealloc(&self, _ptr: *mut u8, _layout: Layout) {
        // Bump allocator: never frees. State-apply discards the store
        // after each event, so the cumulative HEAP_SIZE budget bounds
        // the per-event allocation, not the lifetime allocation.
    }
}
```

```rust
//! Bit-identity check between `crates/sdk/wit/` and the canonical
//! `wit/myrhiza-kernel/wit/`. Prevents WIT drift between the SDK's
//! distributed copy and the source of truth.
//!
//! Per docs/specs/2026-05-26-b-8-sdk-design.md §2.5.

#![allow(clippy::expect_used, clippy::unwrap_used)]

use std::collections::BTreeSet;
use std::path::PathBuf;

#[test]
fn sdk_wit_matches_kernel_wit() {
    let sdk_wit = sdk_wit_dir();
    let kernel_wit = kernel_wit_dir();

    let sdk_files = list_wit_files(&sdk_wit);
    let kernel_files = list_wit_files(&kernel_wit);

    let only_in_sdk: BTreeSet<_> = sdk_files.difference(&kernel_files).cloned().collect();
    let only_in_kernel: BTreeSet<_> = kernel_files.difference(&sdk_files).cloned().collect();

    assert!(
        only_in_sdk.is_empty(),
        "WIT drift: files present in crates/sdk/wit/ but missing from wit/myrhiza-kernel/wit/: {only_in_sdk:?}. Run `just sync-wit`."
    );
    assert!(
        only_in_kernel.is_empty(),
        "WIT drift: files present in wit/myrhiza-kernel/wit/ but missing from crates/sdk/wit/: {only_in_kernel:?}. Run `just sync-wit`."
    );

    // Bit-identity check on every file.
    for name in &sdk_files {
        let sdk_bytes = std::fs::read(sdk_wit.join(name)).expect("read sdk wit file");
        let kernel_bytes = std::fs::read(kernel_wit.join(name)).expect("read kernel wit file");
        assert_eq!(
            sdk_bytes, kernel_bytes,
            "WIT drift: {} differs between crates/sdk/wit/ and wit/myrhiza-kernel/wit/. Run `just sync-wit`.",
            name.display()
        );
    }
}

fn sdk_wit_dir() -> PathBuf {
    PathBuf::from(env!("CARGO_MANIFEST_DIR")).join("wit")
}

fn kernel_wit_dir() -> PathBuf {
    // ancestors().nth(2) → workspace root:
    //   nth(0) is crates/sdk, nth(1) is crates, nth(2) is workspace root.
    PathBuf::from(env!("CARGO_MANIFEST_DIR"))
        .ancestors()
        .nth(2)
        .expect("workspace root is two levels above crates/sdk")
        .join("wit/myrhiza-kernel/wit")
}

fn list_wit_files(dir: &std::path::Path) -> BTreeSet<PathBuf> {
    std::fs::read_dir(dir)
        .unwrap_or_else(|e| panic!("read_dir {}: {e}", dir.display()))
        .filter_map(|entry| {
            let entry = entry.ok()?;
            let path = entry.path();
            if path.extension().and_then(|e| e.to_str()) == Some("wit") {
                Some(PathBuf::from(path.file_name()?))
            } else {
                None
            }
        })
        .collect()
}
```

```rust
//! Dependency-direction check.
//!
//! Asserts that no workspace member under `examples/*` transitively
//! depends on any kernel-internal crate. Per
//! docs/specs/2026-05-26-b-8-sdk-design.md §2.4.

#![deny(missing_docs)]

use std::collections::{HashMap, HashSet, VecDeque};

use cargo_metadata::{Metadata, PackageId};

/// Crates `examples/*` MUST NOT depend on, directly or transitively.
pub const FORBIDDEN: &[&str] = &[
    "myrhiza-kernel",
    "myrhiza-backend",
    "myrhiza-wasmtime-backend",
    "myrhiza-network",
    "myrhiza-test-utils",
    "myrhiza-cli",
];

/// Walk the package graph; return one diagnostic per violating edge.
///
/// Returns an empty `Vec` when the graph is clean. Each entry is a
/// human-readable line `"<example>: transitive dep on forbidden crate <crate>"`.
#[must_use]
pub fn check_dep_direction(metadata: &Metadata) -> Vec<String> {
    let mut violations = Vec::new();
    let id_to_name: HashMap<&PackageId, &str> = metadata
        .packages
        .iter()
        .map(|p| (&p.id, p.name.as_str()))
        .collect();
    let resolve = match metadata.resolve.as_ref() {
        Some(r) => r,
        None => return vec!["error: cargo_metadata returned no resolve graph".into()],
    };
    let node_by_id: HashMap<&PackageId, &cargo_metadata::Node> =
        resolve.nodes.iter().map(|n| (&n.id, n)).collect();

    for package in &metadata.packages {
        let manifest_path = package.manifest_path.as_std_path();
        let in_examples = manifest_path
            .components()
            .any(|c| c.as_os_str() == "examples");
        if !in_examples {
            continue;
        }

        // BFS over the resolve graph rooted at `package.id`.
        let mut visited: HashSet<&PackageId> = HashSet::new();
        let mut queue: VecDeque<&PackageId> = VecDeque::new();
        queue.push_back(&package.id);
        visited.insert(&package.id);

        while let Some(id) = queue.pop_front() {
            let Some(node) = node_by_id.get(id) else {
                continue;
            };
            for dep in &node.dependencies {
                if visited.insert(dep) {
                    let dep_name = id_to_name.get(dep).copied().unwrap_or("<unknown>");
                    if FORBIDDEN.contains(&dep_name) {
                        violations.push(format!(
                            "{}: transitive dep on forbidden crate {}",
                            package.name, dep_name
                        ));
                    }
                    queue.push_back(dep);
                }
            }
        }
    }

    violations
}
```
